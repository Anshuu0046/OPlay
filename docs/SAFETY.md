# What OPlay changes

OPlay reads local launcher manifests and hardware telemetry. A selected optimization can change Windows Game Mode, background capture, GPU preferences and CPU power policy. It records original values before supported changes and checks written values. The process priority guard applies while OPlay is running.

Graphics Studio can swap an existing DLL, directly add a downloaded DLL, install an OptiScaler FSR frame-generation route or install a current DLSS Unlocked community package. The game details panel exposes those install actions and per-game optimization. The MFG and neural actions install the same bundle plus a verified, signed DLSS-G 310.x runtime; the FSR 4 route selects an OptiScaler profile and does not guarantee a particular FSR version. Close the game first; OPlay blocks writes while it detects the game's process. Use community mods in offline or single-player games. OPlay does not bypass anti-cheat, although it no longer blocks file installation based on anti-cheat indicators. Modifying protected or online titles can cause account consequences. OPlay backs up original files, verifies staged writes and supports an explicit restore. Game updates after installation can conflict with restoration; OPlay preserves externally changed files and keeps the original backup. If the mod changes an INI file, OPlay saves that config under `components/recovery` before restore; changed DLLs or other files still stop automatic restore.

OptiScaler and DLSS Unlocked installations temporarily disable existing `dinput8.dll`, `version.dll` and `winmm.dll` files beside the selected game executable. OPlay keeps byte-for-byte backups in the same graphics transaction and restores them when the profile is removed. These files may belong to other mods, so those mods will be inactive while the OPlay profile is installed.

After a graphics install, OPlay launches the game using its saved launcher route and checks the process for 25 seconds after it appears. It watches Windows Application Error events for up to 90 minutes while OPlay stays open. An early crash triggers a full-file preflight, automatic restore of unchanged OPlay-managed files, and a second startup check. A later crash triggers a safe restore and a prompt to run Test launch when ready. OPlay never deletes or overwrites files changed by another tool during that restore. It records launch checks in `%APPDATA%\Aether\components\launch-tests.json` and crash details in the local error log. A successful startup check confirms only that a process stayed open during that interval; it does not verify gameplay, graphics output or later stability. The game remains open after a successful test, so close it before another install or launch check.

GPU offset and V/F curve sessions require Windows administrator approval for the small helper. The helper journals initial values and uses a heartbeat and thermal rollback. This is not proof that a clock is stable under every game. Start with small changes and test your own games. CPU multiplier and RAM timing/frequency overclocking are unavailable on the examined machine.

File installation is not proof that a game loads a DLL or enables frame generation. OPlay does not ship the upstream DLLs in its EXE; the user-selected community package is downloaded from its release and SHA-256 checked. Its own documented requirements include game DLSS/FG inputs. OPlay does not provide a universal engine integration, ReShade or Live Flow screen processing. No measured FPS uplift is claimed for the public release.

Errors are logged locally to `%APPDATA%\Aether\logs\errors.jsonl`. Logs may contain local paths. Inspect them before sharing. See the main [README](../README.md) for technical details.
